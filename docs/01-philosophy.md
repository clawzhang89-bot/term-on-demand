# 核心理念：默认终端，按需 UI

## 问题

远程开发时，你面对的核心矛盾是：

- **终端**：效率最高、延迟最低、零开销，但不擅长可视化（图表、图片、结构化比较）
- **图形界面**：可视化好，但有常驻进程、安全面多、响应慢、处处受限

传统的解决方式是选一个妥协，或者同时开着两个复杂的系统。

## 解法

**用终端的归终端，用浏览器的归浏览器。中间用 AI agent 做桥梁。**

```
默认状态 ──── 终端 (SSH) ──── 95% 时间在这里
  │
  └── 需要看东西时 ── 一句话让 AI 写 HTML
                     │
                     ├── Nginx serve 静态文件
                     ├── 浏览器打开看一眼
                     └── 关掉，回到终端
```

## 关键原则

1. **终端优先** — 不要为了 5% 的可视化需求，牺牲 95% 的终端效率
2. **按需生成，用完即焚** — HTML 页面不是常驻面板，是临时视窗，看完就删
3. **AI 代写，不固定** — 每一张页面都是按你那一刻的需求定制的，不是从固定菜单里挑
4. **零额外后台进程** — Nginx 已经在跑，不需要再装任何后台服务
5. **安全面最小化** — 没有长期开放的管理面板，只有临时的静态文件

## 为什么这比 Cockpit / Webmin 好

| | 传统管理面板 | 这个方案 |
|--|-----------|---------|
| 运行方式 | 常驻进程，一直跑 | 按需生成，用完即焚 |
| 资源占用 | 一直吃内存/CPU | 零开销，除非你在看 |
| 安全面 | 长期开端口，需认证加固 | Nginx serve 静态文件，用完可以删 |
| 灵活性 | 固定功能，很难加 | 写个脚本就是新功能 |
| 调用入口 | 浏览器打开，点菜单 | Terminal 里敲命令 |

## 预制 vs AI 生成的分层策略

不是每次都让 AI 从头写。建立三层能力：

```
第一层：预制脚本（零延迟）
  sysinfo、ls-html、log-view、ps-html...
  敲命令→生成 HTML→浏览器打开

第二层：半预制模板（填参数）
  table.html.sh、chart.html.sh、file-tree.html.sh...
  传入数据→渲染成完整页面

第三层：AI 生成（兜底）
  现有模板不够用时 → AI 现场写 → 效果好就收进预制库
```
